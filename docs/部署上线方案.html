栖桉集 · 免费 / 低花费部署上线方案

适用版本：v1.3.0 ｜ 生成日期：2026-08-12 ｜ 目标：以最低成本把「栖桉集」部署到公网，让其他人也能访问。

一、先想清楚：这个网站需要什么运行环境？

「栖桉集」是 Node.js + Express 后端、数据存 本地 JSON 文件（data/db.json）、配图存 本地文件夹（uploads/）、地图瓦片走 高德（国内 CDN）。因此它需要：

  • 一个能跑 Node.js 的常驻服务器（不是纯静态托管，GitHub Pages / 对象存储托管不了后端）；
  • 持久磁盘——数据文件不能被平台回收（很多"免费 PaaS"实例重启会清空磁盘，数据就没了）；
  • 国内用户访问稳定（站点面向中文用户）。

三、推荐方案 A：国内轻量云服务器（详细步骤）

3.1 购买服务器

  • 进入 腾讯云轻量应用服务器 或 阿里云轻量应用服务器，选 2 核 2G 内存 / 40GB 系统盘 最低档即可；
  • 新用户常有 1-3 年活动价（约 ¥100-400/3 年），学生认证可享更低价；
  • 地域选离你近的城市（华东/华南），系统选 Ubuntu 22.04（或宝塔面板版，方便图形化操作）；
  • 选 固定公网 IP（轻量自带）。

3.2 服务器初始化

# 用 SSH 登录（Windows 用户可用 Xshell / 终端）：
ssh root@你的服务器IP

# 更新系统
apt update && apt upgrade -y

# 安装 Node.js 20（长期支持版）
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs
node -v   # 应显示 v20.x

# 安装进程管理工具 pm2（让网站 7×24 运行、崩溃自动重启）
npm install -g pm2

3.3 部署代码

# 上传代码：任选一种
# 方式一：从 GitHub 拉取（推荐）
git clone https://github.com/LU-km/diary.git /opt/diary
cd /opt/diary

# 方式二：本地打包上传（scp）
# 本地执行： scp -r 项目目录 root@IP:/opt/diary

# 安装依赖（生产模式，不装开发依赖）
npm install --production

# 创建数据目录并启动
mkdir -p data uploads/diaries uploads/avatars
pm2 start server.js --name diary
pm2 save              # 保存进程列表（开机自启）
pm2 startup           # 按提示执行开机自启命令

3.4 配置防火墙（重要！）

# 只开放必要端口：22（SSH）、80（HTTP）、443（HTTPS）
ufw allow 22 && ufw allow 80 && ufw allow 443
ufw enable

3.5 域名 + HTTPS（推荐，不配也能用 IP 访问）

  1. 购买域名：阿里云/腾讯云约 ¥10-60/年（.top 更便宜）；
  2. ICP 备案：国内服务器必须备案（个人备案免费，约 7-20 天）。不想备案→ 用方案 B 境外服务器，或用「域名境外解析 + 服务器境外」组合（但备案是合规要求，正式运营建议完成）；
  3. DNS 解析：域名 A 记录 → 服务器 IP；
  4. 免费 HTTPS 证书：apt install -y certbot && certbot certonly --standalone -d 你的域名（Let's Encrypt，90 天自动续期）；
  5. Nginx 反向代理（把 80/443 流量转给 Node 的 3000 端口，顺便上 HTTPS）：
apt install -y nginx
# 修改 /etc/nginx/sites-available/default：
#   server { listen 443 ssl; ... location / { proxy_pass http://127.0.0.1:3000; } }
#   server { listen 80; return 301 https://$host$request_uri; }
nginx -t && systemctl reload nginx

# 部署在受信反代后：把 config.js 的 TRUST_PROXY 改为 true（获取真实访客 IP）

3.6 数据备份（防止丢数据，必须做）

# 每天凌晨 3 点把数据库和上传文件打包，存到备份目录
crontab -e
# 加入一行：
0 3 * * *  cd /opt/diary && tar czf /root/backup/diary-$(date +\%F).tar.gz data uploads && find /root/backup -name 'diary-*' -mtime +7 -delete

进阶：把备份目录同步到 腾讯云 COS / 阿里云 OSS 免费额度 或 GitHub 私有仓库，防服务器故障。

四、上线检查清单

项目检查项
账号安全登录后台把默认 admin 密码改掉；后台用户管理里确认没有多余管理员
防火墙只开放 22/80/443，3000 端口不要对外开（Nginx 反代即可）
HTTPS浏览器地址栏显示锁图标（证书生效）
地图发布日记选点正常（高德瓦片已本地适配）
审核后台日记审核：把测试日记处理掉（通过/删除）
备份手动执行一次备份命令，确认 tar 包生成
隐私确认 data/、uploads/ 未被 git 追踪（.gitignore 已配置）

六、不推荐与注意

  • 注意 不要用免费 PaaS 直接跑本项目的 JSON 文件存储：免费层重启即丢数据（除非每月多花 ¥20-40 挂持久卷，或改造存储为云数据库/对象存储——属于后续优化，改动较大）；
  • 注意 国内服务器必须 ICP 备案才能绑域名 80/443 正式对外；用 IP 直接访问短期可以，但长期运营建议完成备案；
  • 注意 正式上线前：扩充违禁词库（当前为演示集）、修改默认管理员密码、后台过一遍所有内容审核。

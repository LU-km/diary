栖桉集 · 无审核员的内容审核方案

适用版本：v1.2.0 ｜ 生成日期：2026-08-12 ｜ 目标：在没有专职审核员的情况下，通过多层自动化机制保证社区内容合规，把违规内容拦截在上线前、处置在发生后。

一、总体思路

「无审核员」不等于「无审核」。方案采用五道防线，前四道全自动，最后一道由站长（管理员）事后处理，形成"自动拦截为主 + 人工兜底为辅"的闭环：

防线内容状态
① 关键词敏感词过滤发布 / 评论 / 私信 / 广播四类内容全拦截已落地
② 图片内容安全上传图片格式与内容检测部分落地
③ 用户行为风控限流 / 禁言 / 拉黑 / 注册防护已落地
④ 举报与自动处置用户举报 → 自动下架 / 转人工建议下一步
⑤ 管理后台兜底删除 / 驳回 / 禁言 / 广播警示已落地

二、第一道防线：关键词敏感词过滤（已落地）

2.1 覆盖范围

  • 发布日记（公开 / 仅自己可见均检查）
  • 编辑日记（防止改后注入）
  • 发表评论与回复
  • 发送私信
  • 管理员广播

2.2 拦截策略

  • 命中敏感词 → 直接拒绝提交，并提示命中的词（如：内容包含不当词汇（"××"），请修改后再提交）。无审核员时采用严格拦截而非降权，确保违规内容不出现。
  • 词库可扩展：修改 lib/sensitive.js 的 SENSITIVE_WORDS 数组即可，无需改代码逻辑。

2.3 对抗规避写法

自动归一化后检测：全角→半角、英文大小写混写、去除空格 / 点 / 横线 / 竖线 / 括号等分隔符（如 "垃 圾" "F.U.C.K" "n m s l" 均可命中）。

三、第二道防线：图片内容安全（部分落地）

3.1 已落地：文件格式三重校验

  • 扩展名白名单（jpg / jpeg / png / gif / webp）
  • MIME 类型校验
  • 落盘后魔数（文件头）校验 isRealImage——彻底阻断"伪装成图片的 HTML / 脚本"上传

3.2 建议下一步：图片内容审核 API

方案说明成本
阿里云内容安全 / 腾讯云天御涉黄 / 涉政 / 暴恐识别，准确率高按量计费（约 ¥0.05-0.15 / 千张）
自建 NSFW 模型（开源）如 nudenet / CLIP 微调，需 GPU 或 CPU 推理服务器成本
人工抽查管理员在后台偶尔抽查配图零成本

接入方式：上传后异步调用审核 API，返回 pass / review / block；block 立即删除，review 打标待管理员确认。未接入前，靠格式校验 + 抽查兜底。

四、第三道防线：用户行为风控（已落地）

  • 登录限流：注册 / 前台登录 / 后台登录分桶限流（15 分钟 10 次失败），提示剩余等待时间，防暴力破解与批量注册。
  • 禁言处罚：禁言 1 天 / 1 周 / 永久——期间发布、编辑日记、上传配图、评论、私信全部拒绝（可正常浏览）。
  • 拉黑隔离：被拉黑后无法私信、评论、点赞、收藏、转发对方内容（互动全隔离）。
  • 账号禁用 / 删除：管理员可完全禁用或删除违规账号（级联清理数据）。

五、第四道防线：举报与自动处置（建议下一步）

  1. 每条日记 / 评论增加「举报」按钮（理由：垃圾广告 / 辱骂攻击 / 色情低俗 / 其他）；
  2. 同一内容被 3 个不同用户举报 → 自动转为「仅自己可见」并给管理员发消息；
  3. 同一用户被举报 5 次 → 自动禁言 1 天；
  4. 管理员在后台查看举报记录，决定：放行 / 删除 / 禁言 / 拉黑。

此机制让社区用户参与共治，同时防止恶意举报（仅统计不同用户的举报，且被驳回的举报不计入）。

六、第五道防线：管理后台兜底（已落地）

能力入口
日记审核（通过 / 驳回 / 删除）后台 → 日记审核
用户处罚（禁用 / 删除 / 禁言 / 拉黑）后台 → 用户管理
全站广播（警示 / 公告）后台 → 仪表盘
评论删除（违规评论）前台详情页（管理员有删除按钮）

七、内容分级策略

严重程度示例自动处理
高危（涉政 / 涉黄 / 暴力）命中高危敏感词、NSFW 图片直接拦截 + 通知管理员
中危（辱骂 / 引战）命中常规敏感词直接拦截（当前）→ 可放宽为"转待审"
低危（疑似广告）含链接、重复内容建议：相似内容检测降权 / 标记

八、建议实施路线图

阶段动作工作量
现在（v1.2.0）敏感词四通道拦截 + 图片格式校验 + 风控处罚 + 后台兜底已完成
下一步举报与自动处置机制（第四道防线）约 1-2 天
上线前扩充敏感词库（按平台定位）约 1 小时
有量后接入图片审核 API / 相似内容检测约 1-3 天

九、重要提醒

1. 敏感词库目前是最小演示集（约 12 个词），正式上线前必须按平台定位扩充（参考网信办内容安全规范 + 平台公约自行增删）。
2. 自动审核是「降低风险」而非「消除风险」：遇到拿不准的内容，宁可拦截。
3. 若接入第三方审核 API，需在隐私说明中告知用户（内容可能被第三方处理）。
